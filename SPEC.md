# Техническая спецификация: Универсальный фреймворк выгрузки учебных курсов (Playwright + Python)

Документ задаёт архитектуру, контракты модулей, требования безопасности и инженерные ограничения для создания переиспользуемых скриптов выгрузки учебных материалов с любых веб-площадок (LMS, корпоративные порталы, SPA и фреймовые СДО).

---

## 1. Архитектура и модульная структура проекта

Система строится как набор независимых CLI-утилит поверх общего ядра. Модули связаны единым контрактом директорий, аргументов командной строки (`--dir`, `--cdp`, `--out`) и кодов возврата:
* `0` — успешное завершение;
* `1` — критическая ошибка среды (нет подключения к CDP, не найден курс, отсутствует FFmpeg или исходная папка);
* `2` — завершение с частичными ошибками (часть файлов не скачалась, не прошла проверку или защищена DRM).

```text
course-scraper/
├── web-page-reverse-engineering/ # HTML/MHTML-срезы и очищенные HAR-дампы (в .gitignore!)
├── core/                         # Переиспользуемое ядро (не зависит от конкретной LMS)
│   ├── browser.py                # Подключение по CDP, префлайт порта/вкладок, контроль сессии
│   ├── downloader.py             # Последовательный CDP-загрузчик + валидация magic bytes
│   ├── state.py                  # Атомарное управление состоянием (manifest.json, state.json)
│   ├── fs_utils.py               # Санитизация имён, zero-padding, лимиты MAX_PATH
│   ├── models.py                 # Строгие модели данных (Course, Module, Item, ItemStatus)
│   └── handlers/                 # Стратегии извлечения по типам контента
│       ├── binary_file.py        # PDF, Office-документы, архивы
│       ├── video_stream.py       # Прямое видео (.webm/.mp4) и HLS/DASH (+ DRM-детектор)
│       ├── composite_html.py     # HTML-страницы со встроенным видео, текстом и картинками
│       ├── assignment.py         # Страницы заданий (условие + вложения + решения)
│       └── test_readonly.py      # Разбор завершённых тестов (строго read-only)
├── adapters/                     # Сайт-специфичная логика (1 файл = 1 платформа)
│   ├── base.py                   # Абстрактный интерфейс + утилиты (scroll_to_bottom и др.)
│   └── <platform_name>.py        # Селекторы, парсинг оглавления, извлечение URL
├── scripts/                      # Точки входа (отдельные CLI-скрипты)
│   ├── download_course.py        # 1. Основной скрипт скачивания материалов
│   ├── verify_course.py          # 2. Онлайн/оффлайн аудит целостности + очистка (--clean)
│   ├── convert_to_mp4.py         # 3. Пакетная конвертация видео в универсальный .mp4
│   ├── split_materials.py        # 4. Read-only разделение документов, видео и HTML
│   ├── zip_folders.py            # 5. Универсальная архивация любых папок в .zip (Zip64)
│   └── sanitize_capture.py       # 6. Очистка HAR/HTML от cookies, токенов и ПДн (опционально)
├── scrape-course.ps1             # Интерактивный оркестратор для Windows (UTF-8 with BOM)
├── scrape-course.sh              # Интерактивный оркестратор для Linux / WSL (опционально)
└── README.md                     # Инструкция по запуску и диагностике
```

### 1.1. Изоляция зависимостей
Модули не должны тянуть лишние зависимости друг друга:
* **Базовая среда:** Python 3.10+.
* **`playwright`:** требуется только для `download_course.py` и онлайн-режима `verify_course.py`. Команда `playwright install` **не выполняется** — используется уже установленный в системе Chromium-браузер (Google Chrome, Яндекс Браузер, Edge).
* **`ffmpeg` / `yt-dlp`:** требуются только для `convert_to_mp4.py` и обработчика потокового видео (`video_stream.py`). После установки через `winget` на Windows требуется перезапуск терминала для обновления `PATH`.
* **Только стандартная библиотека Python:** `split_materials.py`, `zip_folders.py`, `sanitize_capture.py` и оффлайн-режим `verify_course.py`.

### 1.2. Управление состоянием и манифест (`core/state.py`)
В корневой папке скачанного курса поддерживаются два JSON-артефакта (запись строго атомарная: во временный файл `.tmp` с последующим `os.replace()`):
* **`manifest.json`** — нормализованное дерево курса (`Course -> Module -> Item`), сформированное адаптером. Развязывает этап парсинга от этапа скачивания.
* **`state.json`** — локальный трекер статусов каждого `item_id`: `PENDING`, `DONE`, `FAILED` (с текстом ошибки), `DRM_LOCKED`, `EXTERNAL_LINK`, `SKIPPED`, а также локальный путь и размер файла.
* **Логика повторного запуска:** если элемент имеет статус `DONE` и файл существует на диске с ненулевым размером, шаг пропускается мгновенно. Полный бинарный аудит magic bytes при повторном запуске выполняется только через `verify_course.py` (или флаг `--force-recheck`).

### 1.3. Детерминированное именование и гигиена ФС (`core/fs_utils.py`)
Единая функция нормализации используется во всех модулях:
* **Лексикографическая сортировка (Zero-Padded Naming):**
  * папка модуля: `M<ID:02d>_<Название>` (например, `M01_Введение`);
  * файл или папка элемента: `<ID:02d>_<Тип>_<Название>.<ext>` (например, `01_Doc_Конспект.pdf`, `02_Vid_Лекция.mp4`, `03_Task_Практика/`). При количестве элементов ≥100 разрядность автоматически расширяется до `03d`.
* **Совместимость с Windows:** удаление запрещённых символов (`<>:/\|?*`), защита от зарезервированных имён (`CON`, `PRN`, `AUX`, `NUL`, `COM1–9`, `LPT1–9`), безопасная обрезка длинных заголовков для соблюдения лимита `MAX_PATH = 260`.

## 2. Подключение к браузеру (Zero-Credentials CDP)

Логины, пароли, токены и `storage_state.json` нигде не хранятся. Скрипты подключаются к живой авторизованной сессии браузера через `playwright.chromium.connect_over_cdp(cdp_url)`.

### 2.1. Правила запуска отладочного браузера
1. **Изолированный профиль строго в ASCII-пути:** актуальные версии Chromium блокируют CDP на дефолтном профиле, а кириллица в `$env:USERPROFILE` ломает разбор `--user-data-dir` (особенно в Яндекс Браузере). Всегда использовать путь на латинице: `--user-data-dir="C:\Users\Public\<browser>-debug"`.
2. **Явная привязка к IPv4 и полезные флаги:** передавать `--remote-debugging-port=9222 --remote-debugging-address=127.0.0.1 --disable-dns-prefetching --no-first-run` (опционально — сразу передавать стартовый URL площадки в аргументах запуска).

### 2.2. Префлайт-проверка и Runbook восстановления порта (`core/browser.py`)
Перед началом работы `browser.py` опрашивает `GET http://127.0.0.1:<port>/json/version` и `/json/list`, выводя имя браузера и список открытых вкладок. Это сразу выявляет конфликт, когда закрытый браузер остался висеть фоновым процессом и удерживает порт `9222`.

Если порт занят чужим/зависшим процессом (Windows PowerShell):
```powershell
Get-NetTCPConnection -LocalPort 9222 -State Listen -ErrorAction SilentlyContinue |
    Select-Object -ExpandProperty OwningProcess -Unique |
    ForEach-Object { Stop-Process -Id $_ -Force }
Stop-Process -Name chrome, browser -Force -ErrorAction SilentlyContinue
```

### 2.3. Обработка истечения сессии (Session Expiration Circuit Breaker)
На длинных курсах серверная сессия может истечь по таймауту. Если загрузчик получает серию (например, 2–3 подряд) ответов `401`/`403` или редиректов на страницу логина, он **не продолжает** прогон с ошибками, а:
1. сохраняет текущий `state.json`;
2. встаёт на интерактивную паузу с запросом обновить авторизацию в открытом браузере (или завершается с кодом `1` в неинтерактивном режиме).

## 3. Этап 1: Реверс-инжиниринг площадки и гигиена приватности

Перед написанием адаптера в `adapters/<platform>.py` проводится аудит площадки через DevTools (`Elements` + `Network` с включённым `Preserve log`):

1. **Топология навигации:** определить тип приложения — MPA (уникальные URL), SPA (один URL, динамический DOM) или фреймы (`iframe`/`frameset`, где контент ищется перебором `page.frames`).
2. **Структура оглавления:** найти контейнеры модулей и элементов, атрибуты типа контента (отделить лекции от тестов и внешних ссылок), проверить свёрнутые блоки (`display: none` — читать названия через `textContent`, а не `innerText`) и пагинацию/ленивую подгрузку.
3. **Утилита прокрутки (`adapters/base.py`):** реализовать метод `scroll_to_bottom(page, container_selector=None, idle_sec=2.0, max_scrolls=100)` для SPA с бесконечным скроллом, останавливающийся, когда высота контейнера перестаёт расти или достигнут лимит итераций.
4. **Механика доставки контента:** отследить цепочку от клика до файла — прямая выдача, HTTP/JS-редиректы, прокладки вида `redirect.asp?url=...` (проверить кодировку параметров: `utf-8` vs `windows-1251`), `popup`-окна, встроенный PDF.js (`?file=`), HLS/DASH-потоки или сторонние `iframe`.
5. **Границы безопасности и приватности:**
   * зафиксировать кнопки с побочными эффектами («Начать тест», «Сдать работу») — скрейпер никогда их не активирует;
   * папка `web-page-reverse-engineering/` с сохранёнными HTML/HAR-срезами **всегда добавляется в `.gitignore`**; перед любым шарингом или отправкой в ИИ дампы прогоняются через `scripts/sanitize_capture.py`.

## 4. Этап 2: Ядро загрузчика и обработчики форматов

### 4.1. Правила движка загрузки (`core/downloader.py`)
* **Нативное скачивание через Chrome CDP:** бинарные файлы загружаются средствами браузера (`Browser.setDownloadBehavior` в режиме `allowAndName` + программный `<a download>`), а не через `requests`. Это использует TLS-стек (BoringSSL), куки и прокси браузера и исключает ошибки OpenSSL (`SSL: UNEXPECTED_EOF_WHILE_READING`).
* **Строго последовательное скачивание (Strict Sequential Downloading):** во избежание Race Condition при сопоставлении CDP-событий, загрузки идут строго по одной. Ядро дожидается `Browser.downloadWillBegin` (фиксирует `guid`), отслеживает `Browser.downloadProgress` (с таймаутом зависания) до `state == "completed"`, валидирует `tmp_dir / guid`, перемещает файл в целевую папку и только затем переходит к следующему элементу.
* **Защита от WAF (Rate Limiting & Jitter):** между логическими переходами встроена случайная задержка `time.sleep(random.uniform(delay_min, delay_max))` (по умолчанию `1.0–3.5` сек, настраивается через CLI).
* **Умное ожидание всплывающих окон (Popup Await):** при перехвате `context.on("page")` ядро не закрывает вкладку мгновенно, а ждёт появления целевого URL / старта загрузки или таймаута (по умолчанию `5.0` сек), после чего закрывает popup и сбрасывает рабочую вкладку на `about:blank`.
* **Мгновенная валидация magic bytes:** файл проверяется **до** переноса из `_tmp_downloads`. Если внутри обнаружен HTML (`<!doctype`, `<html`), размер `0 B` или битый заголовок — временный файл удаляется, а в `state.json` пишется `FAILED`.
* **Отложенное разрешение Signed URLs (Lazy URL Resolution):** для LMS с краткоживущими подписанными ссылками (S3/CloudFront/Kinescope с TTL 5–15 минут) в `manifest.json` хранится стабильный `lesson_url` / `item_ref`, а прямой URL файла запрашивается через адаптер непосредственно перед загрузкой элемента. При `403` с истёкшей подписью (`Expires`/`X-Amz-Expires`) выполняется 1 переразрешение URL до срабатывания Session Circuit Breaker.
* **Cross-Origin Fallback без `Content-Disposition: attachment`:** Chromium игнорирует атрибут `<a download>` для кросс-доменных URL без `Content-Disposition: attachment` (открывая PDF/видео во вкладке вместо скачивания). При таком ответе загрузчик переключается на резервный канал: `fetch(url, { credentials: "include" })` → `Blob` → `<a download>` внутри контекста страницы либо `context.request.get(url)` с куками и `Referer` активной сессии.

### 4.2. Матрица обработчиков контента (`core/handlers/`)

| Формат материала | Механизм извлечения | Артефакт на диске | Валидация |
| :--- | :--- | :--- | :--- |
| **Документы (PDF, лекции, презентации, Office)** | Перехват URL в `route`/`response` или парсинг `?file=` PDF.js; скачивание через CDP | `01_Doc_Название.pdf` (`.docx`, `.pptx`) | `%PDF-` + `%%EOF` в хвосте; `PK\x03\x04` для Office; отсутствие `<html` |
| **Отдельное видео (`.webm`, `.mp4`, `.mkv`)** | Перехват `response`, `popup` (с Popup Await) и декодирование редиректов (`utf-8` → `cp1251`); скачивание через CDP | `02_Vid_Название.webm` (или `.mp4`) | `\x1a\x45\xdf\xa3` (EBML) для WebM/MKV; `ftyp` для MP4/MOV |
| **Потоковое видео (HLS `.m3u8` / DASH `.mpd`)** | Перехват манифеста + `Cookie`/`Referer`/`User-Agent`. **Предварительная проверка на DRM** в памяти: поиск `SAMPLE-AES`, `SAMPLE-AES-CTR`, Widevine/FairPlay UUID, `<ContentProtection>` (обычный `AES-128` — не DRM, скачивается штатно). При наличии DRM — статус `DRM_LOCKED`, без скачивания. Иначе — передача в `yt-dlp`/`ffmpeg` | `02_Vid_Название.mp4` | `ffprobe` (длительность > 0, наличие видео/аудиодорожек) |
| **Составная HTML-страница (текст + встроенное видео + картинки)** | Выделенная папка урока: 1) очищенный DOM статьи → Markdown/HTML (или `page.pdf()`); 2) скачивание `<img>` и вложений в `assets/` с переписыванием ссылок на локальные; 3) извлечение встроенных `<video>` / `<iframe>` через `video_stream.py` в ту же папку | `03_Page_Название/`<br>├── `lesson.md`<br>├── `video_01.mp4`<br>└── `assets/...` | Непустой текст (не страница логина), все локальные медиа прошли проверку magic bytes |
| **Задания (практика, лабораторные)** | Извлечение условия, критериев, вложенных шаблонов и (при наличии) ответа студента | `04_Task_Название/`<br>├── `task.md`<br>└── `attachments/...` | Непустое описание, валидные вложения |
| **Тесты (только завершённые / разбор)** | Строго read-only: сбор вопросов, вариантов, ответов и пояснений в JSON + Markdown. Для формул MathML/LaTeX/SVG — скриншот узла с **временной инъекцией светлого CSS** (`background: #fff !important; color: #000 !important; padding: 10px;` + контрастные `fill`/`stroke` для SVG), удаляемого сразу после снятия скриншота | `05_Test_Название.json`<br>`05_Test_Название.md`<br>`images/...` | Совпадение числа вопросов со счётчиком теста |
| **Внешние ссылки** | Фиксация URL с привязкой к модулю без скрейпинга чужого домена | `external_links.txt` + статус `EXTERNAL_LINK` | Валидный URL |

| :--- | :--- | :--- |

## 6. Этап 4: Оркестратор ОС (`scrape-course.ps1` / `scrape-course.sh`)

Единая интерактивная точка входа, ведущая диалог с пользователем:
* **Окружение Windows:** файл `.ps1` с кириллицей **обязательно сохраняется в UTF-8 with BOM** (Windows PowerShell 5.1 читает `.ps1` без BOM как Windows-1251 и падает с ошибкой парсера). В начале скрипта выставляются UTF-8 для консоли и `$env:PYTHONUTF8 = "1"`. Запуск выполняется с флагом `-ExecutionPolicy Bypass` (либо через `pwsh` 7+).
* **Меню действий:**
  1. Запустить отладочный браузер (или проверить/освободить порт CDP).
  2. Скачать / докачать курс (`download_course.py`).
  3. Проверить целостность и очистить битые файлы (`verify_course.py`).
  4. Конвертировать видео в `.mp4` (`convert_to_mp4.py`).
  5. Разделить материалы (`split_materials.py`).
  6. Упаковать папки в `.zip` (`zip_folders.py`).
  7. Полный цикл (`Скачать → Проверить → Конвертировать`) с остановкой при коде возврата `1`.
  8. Изменить рабочую папку `--dir` или адрес `--cdp`.

## 7. Реестр учтённых ошибок (Postmortem Baseline)

Все проблемы, выявленные на практике, зафиксированы как базовые инварианты архитектуры:

| Проблема | Первопричина | Инвариант в спецификации |
| :--- | :--- | :--- |
| Обрыв `requests` с `SSL: UNEXPECTED_EOF_WHILE_READING` | Несовместимость OpenSSL 3.x со старыми серверами/прокси | Нативная загрузка через CDP браузера (`core/downloader.py`) |
| Ложный `OK -> 0.00 MB` и битые `.webm` | `redirect.asp?url=...` (в `cp1251`) открывал popup; fallback скачал HTML редиректа как `.webm` | Popup Await + декодирование `utf-8`/`cp1251` + проверка magic bytes до переноса файла |
| `.webm` не открывается в плеере Windows | Контейнер WebM (VP8/VP9 + Opus) не поддерживается из коробки | Отдельный `convert_to_mp4.py` с `yuv420p` и чётными размерами кадра |

## 8. Расширение (Phase 2): Генерация адаптеров с помощью ИИ (Generative Adapters)

Поскольку контракты `core/models.py` и `adapters/base.py` жёстко зафиксированы, фреймворк позволяет подключать LLM с большим контекстным окном для ускоренной разработки новых адаптеров `adapters/<platform>.py`:

1. **Сбор и обязательная санитизация контекста:** пользователь сохраняет HTML-страницу оглавления и сетевой дамп (HAR) из DevTools, после чего **обязательно прогоняет их через `scripts/sanitize_capture.py`** (вырезание `Cookie`, `Authorization`, `Set-Cookie`, токенов и персональных данных). Неочищенные HAR-файлы передавать во внешние LLM API **запрещено**.
2. **Генерация по строгому контракту:** в системный промпт подаются `core/models.py`, `adapters/base.py` и очищенные дампы. Промпт запрещает LLM писать собственную логику скачивания — адаптер обязан только возвращать нормализованные объекты `Course / Module / Item`.
3. **Изолированная проверка (Sandboxed Fixture Evaluation):** сгенерированный адаптер тестируется на сохранённых оффлайн HTML-фикстурах в изолированной среде (контейнер без сети / без доступа к живому CDP). При ошибке парсинга traceback может передаваться в LLM для итерации исправления (Self-Healing Loop).
4. **Обязательный Human-in-the-Loop перед боевым запуском:** перед подключением нового адаптера к реальной авторизованной сессии браузера разработчик вручную проверяет код адаптера (в особенности отсутствие кликов по деструктивным кнопкам и тестам).
